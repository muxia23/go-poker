# go-poker 账号与三级权限设计

日期：2026-11-01
状态：待用户审阅

## 目标

把 go-poker 改成只供自己和朋友使用的私人牌局站：

- 每个人都必须用「账号 + 密码 + 邀请码」注册，登录后才能访问游戏。
- 三级权限：root 管理所有账号，admin 可以创建对局，普通用户只能加入对局。
- 加入对局仍然是输入房间号。
- 入口改为 `https://poker.example.com/poker`，根路径返回 404。

**完成标准：** 没有有效会话的访客拿不到游戏代码，也连不上 WebSocket；所有权限都在服务端校验，绕过界面直接发请求也无效。

## 不做的事

- 跨场战绩和长期排行榜（唯一用户名为以后留了条件，这次不做）
- 邮箱验证、找回密码邮件、两步验证、第三方登录
- 牌局界面汉化（登录、注册和账号管理页用中文，牌局界面保持英文）
- 删除账号（只允许禁用，保证历史账单能对应到账号）

## 权限

| 操作 | root | admin | user |
|---|---|---|---|
| 输入房间号加入对局 | ✓ | ✓ | ✓ |
| 创建对局 | ✓ | ✓ | ✗ |
| 修改自己的密码和用户名 | ✓ | ✓ | ✓ |
| 查看账号、设置 admin/user、禁用/启用、重置密码 | ✓ | ✗ | ✗ |
| 生成、查看、作废邀请码 | ✓ | ✗ | ✗ |

- 系统只有一个 root。它不能被禁用或降级，也不能通过界面新增第二个 root。
- 牌桌内的房主权限（踢人、调整筹码等）沿用原逻辑，与站点角色无关。root 和 admin 不会因为站点角色获得别人牌桌的房主权限。
- 新注册账号一律是 user，由 root 手动提升为 admin。

## 账号规则

**身份**

- 每个账号有一个注册时生成、永不改变的 UUID。会话、角色、邀请码使用记录和牌桌座位都关联 UUID，不关联用户名。

**用户名**

- 全站唯一，不区分大小写：`Alice` 和 `alice` 算同一个名字。
- 注册和改名时都由数据库唯一索引检查，重名直接失败。牌桌上不再需要处理重名账号。
- 长度 2 到 20 个字符，允许中文、字母、数字、下划线和连字符，不允许空格。
- 比较前先做 Unicode NFC 规范化，并按规范化后的小写形式建唯一索引。
- 保留系统名（`table.SystemName`）。
- 添加机器人时，名字不能与已有账号相同，否则账单里无法区分。
- 可以修改，但账号在任何未关闭的牌桌上（入座、旁观或断线保留座位期间）时不能改，提示先离开牌桌。改名后旧名字立刻释放，其他人可以注册或改用。

**密码**

- 至少 8 个字符，用 bcrypt 保存哈希值。root 也看不到明文。
- root 重置密码时生成一个临时密码并只显示一次；该账号下次登录必须先改密码。

**邀请码（一人一码）**

- 由 root 生成，每个码只能注册一个账号，默认 7 天过期。
- 随机生成至少 80 位熵，数据库只存哈希值，明文只在生成时显示一次。
- 用码和建号在同一个数据库事务内完成，两个人不可能用同一个码注册成功。
- 用户名重复或密码不合格时不消耗邀请码。
- root 可以作废未使用的码，并能看到每个码的状态（未使用、已使用及使用者、已过期、已作废）。

**root 账号的初始化和找回**

- 首次启动且系统没有 root 时，用环境变量 `ROOT_USERNAME` 和 `ROOT_PASSWORD` 创建，首次登录必须改密码。之后这两个变量不再生效。
- 忘记密码时，在服务器上运行 `docker exec go-poker ./main reset-root`，输出一个临时密码。

## 访问流程

```
poker.example.com/                → 404（Nginx）
/poker、/poker/*（未登录）         → 跳转 /poker/login?next=<站内相对路径>
/poker/login                      → 登录和注册页（不加载游戏代码）
/poker/api/auth/*                 → 登录、注册接口
/poker、/poker/_next/*（已登录）   → 游戏
/poker/ws（已登录）                → WebSocket，未登录在握手阶段返回 401
/poker/accounts、/poker/api/admin/* → 仅 root，其他角色 403
```

- 登录页是 Go 内嵌的独立小页面，不含游戏代码。
- `next` 只接受以 `/poker` 开头的站内路径，防止跳转到外部网站。
- 牌桌链接 `/poker?table=xxx` 继续可用：未登录的人先登录，然后回到这张牌桌。

**会话**

- 登录成功后写入随机令牌 Cookie `poker_session`，属性为 `HttpOnly; Secure; SameSite=Lax; Path=/poker`，数据库只存哈希值。
- 有效期 30 天，使用时自动续期。
- 退出登录、改密码、被重置密码、被禁用时，服务端删除会话并立刻断开该账号的 WebSocket。

**接口防护**

- 所有改变状态的请求都校验 Origin。
- 登录和注册按 IP 和用户名限频：15 分钟内失败 5 次即暂时拒绝。这部分计数放在内存里，重启后清零。
- 登录失败统一提示「用户名或密码错误」，不透露账号是否存在。

## 牌桌身份

- WebSocket 连接在握手时绑定账号，消息里的 `username` 字段被忽略，牌桌名字取自账号用户名。
- `create-table` 在服务端校验角色，user 发送时直接拒绝。
- 公开牌桌列表关闭：`public` 强制为 false，`list-tables` 返回空，首页不显示列表和开关。要进牌桌必须知道房间号。
- 牌桌密码功能保留，作为可选项。
- **同一账号换设备：** 按 UUID 判断。账号在牌桌上已有座位时，新连接接管这个座位，旧连接被断开。令牌重连机制继续保留。
- **离桌后改名：** 牌局中不能改名。牌桌保存「UUID → 入桌时的名字」映射，并随牌桌状态持久化。离桌改名后回到同一张未关闭的牌桌，仍显示原来的名字，账单和统计不会被拆成两行；新名字从下一张牌桌开始生效。
- **旧名字被别人使用：** 如果某个名字已被牌桌映射给另一个 UUID，新账号用这个名字加入该桌时会被拒绝，提示对方改名或换桌，避免继承别人的账单行。

## 代码结构

| 单元 | 位置 | 职责 |
|---|---|---|
| 账号模块 | `backend/auth/`（新增） | 账号、邀请码、会话、限频、密码处理；不依赖牌局代码 |
| HTTP 接入 | `backend/server/` | 中间件、路由、`BASE_PATH`、WebSocket 绑定账号和校验角色 |
| 数据库 | `backend/server/migrations/003_accounts.sql`（新增） | `accounts`、`invites`、`sessions` 三张表，兼容 SQLite 和 Postgres |
| 登录页 | Go 内嵌 HTML | 登录、注册、首次改密码 |
| 账号管理页 | `web/pages/accounts.tsx`（新增） | root 管理账号和邀请码 |
| 首页 | `web/components/Join.tsx` 等 | 去掉名字输入，显示当前账号和退出按钮；user 不显示创建按钮 |
| 前端路径 | `next.config.js`、`WebSocket.tsx` | `basePath: '/poker'`，WebSocket 地址带前缀 |
| 牌局引擎 | `backend/holdem/`、`backend/table/` | 尽量不动，只增加「按 UUID 接管座位」和「UUID → 名字映射」 |

**失败时默认关闭：** 账号系统没有开关。未配置 `DATABASE_URL` 时，程序拒绝启动，而不是退回无登录模式。生产入口没有有效会话时一律返回 401；上游大量按名字建连的单元测试直接调用内部函数，不经过这个入口，以减少改动，入口本身另有测试覆盖。

## 错误处理

| 情况 | 行为 |
|---|---|
| 邀请码错误、已使用、已过期或已作废 | 注册失败，统一提示「邀请码无效」 |
| 用户名已存在 | 注册或改名失败，提示用户名已被占用；注册时不消耗邀请码 |
| 账号被禁用 | 登录被拒绝；在线连接立刻断开，座位按原有断线规则处理 |
| 会话过期 | WebSocket 断开后重连失败，页面跳转到登录页 |
| 数据库不可用 | 接口返回 503，不放行任何请求 |

## 测试

**后端（Go，先写失败的测试）**

- 用户名唯一：注册和改名都检查；大小写、Unicode 规范化；保留名；与机器人名字冲突；并发抢同一个名字
- 改名：UUID、会话和角色不变；在牌桌上改名被拒绝；离桌改名后回原桌账单仍为一行，下一张牌桌用新名字；旧名字被他人占用后不能继承旧牌桌的账单行
- 邀请码：一次性、过期、作废、并发抢用同一个码、注册失败不消耗
- 会话：过期、退出、改密码、禁用后立刻失效
- 权限：user 直接发送 `create-table` 被拒绝；user 和 admin 调用 root 接口返回 403
- root 不能被禁用或降级
- 绕过：未登录访问页面、静态文件和 WebSocket；伪造消息里的 `username`；跳转参数指向外站
- 限频：达到次数后被拒绝

**端到端（沿用仓库的 e2e 脚本，手机尺寸）**

- root 生成邀请码 → 朋友注册 → 提升为 admin → 开桌 → 另一个 user 输入房间号加入 → 打完一手
- 同一账号换设备接管座位
- 在牌桌上改名被拒绝；离桌改名后回到原牌桌，账单仍为一行
- 禁用账号后，该用户立刻掉线且无法再登录

**上线验证**

- 从公网确认 `/`、`/poker/_next/*`、`/poker/ws` 未登录时都拿不到内容
- 从另一台服务器确认容器端口不对外开放

## 部署

- 保留上游 MIT 协议。
- 在服务器上构建本地镜像，用 compose 运行，容器只监听 `127.0.0.1`。
- 使用全新的数据库。现有数据只有部署测试用的 `deploytest`，不迁移。
- Nginx 改为只转发 `/poker`，其余路径返回 404，同时删除现在的邀请链接 Cookie 门禁和 `/join/<key>`，旧邀请链接随之失效。
- root 初始密码随机生成，保存在服务器上权限为 600 的环境变量文件中，并在交付时告诉用户。
- 新版验证通过后才切换 Nginx；切换失败时恢复原配置和原容器。

## 已知限制

- `/poker` 路径只是遮挡，不是安全边界。真正的防护是登录和服务端权限校验。
- 无法阻止朋友把账号借给别人，但 root 可以随时禁用账号并断开连接。
- 上游后续更新需要手动合并。账号逻辑集中在独立模块，以减少冲突。
